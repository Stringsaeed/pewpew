# Unit U5: synth engine, SFX, four music tracks

Owns: src/sound.ts, src/audio.ts, src/audio.test.ts, and a fake Web Audio graph for tests at src/testing/fake-audio.ts. Works in its own git worktree /Users/saeed/.t3/projects/pewpew-audio on branch `u5-audio` (node_modules warmed). Node only; never builds or launches the app. Audio on the simulator cannot be captured, so the proof is a deterministic test against a fake AudioContext that records every node, connection, param automation, and start/stop time.

Deliver, in order:
1. `src/audio.ts`: createAudio() that calls AudioManager.setAudioSessionOptions({ iosCategory: 'playback', iosMode: 'default' }) before constructing the AudioContext, and accepts an injectable context factory so tests pass a fake. Engine: a Patch interpreter (oscillator or noise buffer source, optional detuned second oscillator, BiquadFilter with envelope on frequency, ADSR on a GainNode, pitch sweep via frequency.exponentialRampToValueAtTime), a voice cap per SfxId (drop the oldest when exceeded), and a 25 ms lookahead sequencer (setInterval) scheduling tracker steps 120 ms ahead on ctx.currentTime, looping. Music state has one owner: start event picks tierOf(level)'s song, bossEnter switches to boss, won and lost play the complete or gameover stinger and stop music. ui(cue) plays tap and starts or stops the title music. mix() applies two master gains. active(false) suspends the context and the sequencer together. Dispose cleanly.
2. `src/sound.ts`: tune the seven patches and add any you need. SFX for all 8 ids (laser, hit, explode, pickup, shield, complete, gameover, tap) as short note lists with maxVoices. SONGS for tier1, tier2, tier3, boss: original compositions, 8 bars each at 16th-note resolution, at least 3 voices each (lead, bass, drums via kick and hat patches), with a distinct key and feel per tier (tier1 bright and simple around 120 bpm, tier2 minor and driving around 132, tier3 tense and syncopated around 144, boss heavy and fast around 160). Tracker strings: "C4" strike, "-" hold, "." rest, one token per 16th. A test asserts every voice in a song has the same token count and every token parses.
3. Tests (node:test): patch interpreter creates the expected node graph for each patch kind; ADSR times are scheduled in order; sweep ramps to the right target; voice cap evicts oldest; sequencer schedules exactly the notes of bar 1 within the lookahead and then bar 2 on the next tick; tier switching stops old voices; won stops music; mix gains applied; EVENT_SFX covers every SimEvent name (compile-time already, but assert the runtime record too).
4. A tiny `scripts/render-song.ts` (tsx) that renders any song or sfx to a 16-bit WAV in /tmp via the same patch interpreter over a software mixer (sine, square, saw, triangle, noise, biquad, ADSR). This is the review lever: the human can listen. Render all four songs and the eight SFX, and list the file paths and durations in your report. Keep it simple; it is not the runtime engine but it must share the Patch and Song data.

Done when typecheck and `npm test` pass and the WAVs exist. Report file paths, durations, and bpm, key, and bar count per song.
